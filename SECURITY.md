# Security Policy

## Reporting a vulnerability

Do **not** publish exploitable details in a GitHub issue. Email `sanskarin@outlook.in` with the affected version, platform, reproduction steps, impact, and any suggested mitigation. Avoid attaching real vaults, master passphrases, keys, or private data.

The project will acknowledge reports when maintainers are available, investigate reproducible findings, and publish fixes/advisories when appropriate. No guaranteed response window is promised.

## Scope

The local client, encrypted vault format, backup/restore path, import parsers, dependency chain, and lock lifecycle are in scope. Social engineering, compromised operating systems, rooted/jailbroken-device guarantees, and attacks requiring already-authorized arbitrary code execution are documented limitations rather than claims of full protection.

## Audit status

The project has **not** completed an independent professional security audit. Users with high-risk threat models should wait for an audit and review the threat model before relying on CipherNest.
